# Initial branch-length guess allocates Vec<Sub> per edge for count only

`InitialGuessEvidence::gather()` ([packages/treetime/src/optimize/gather.rs#L73-L84](../../packages/treetime/src/optimize/gather.rs#L73-L84)) counts the substitutions of each edge by calling `edge_subs()` and taking `.len()`, discarding the substitution vector. The optimize pipeline gathers this evidence before the loop ([packages/treetime/src/optimize/pipeline.rs#L110](../../packages/treetime/src/optimize/pipeline.rs#L110)) and passes the counts to `fn guess_initial_branch_lengths()` ([packages/treetime/src/optimize/dispatch.rs#L177](../../packages/treetime/src/optimize/dispatch.rs#L177)). For dense partitions, `edge_subs()` ([packages/treetime/src/partition/marginal/dense/partition.rs#L80-L111](../../packages/treetime/src/partition/marginal/dense/partition.rs#L80-L111)) builds a `Vec<Sub>` with one entry per differing site. The count runs across every edge before optimization. The dense branch of `edge_sub_count()` ([packages/treetime/src/partition/marginal/reconstruction.rs#L229-L234](../../packages/treetime/src/partition/marginal/reconstruction.rs#L229-L234)), which timetree polytomy resolution uses, counts the same way.

A count-only method (incrementing a counter instead of pushing `Sub` values) would avoid the allocation. For small alignments the cost is negligible. For large alignments (thousands of positions, hundreds of edges) the cumulative allocation is avoidable.

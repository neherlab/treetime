# Indel policy variants lack output tests

The two indel policies of branch-length optimization (`IndelPolicy::Include`, `IndelPolicy::Exclude`, selected by `--no-indels`) have unit tests of their terms in [packages/treetime/src/optimize/__tests__/test_indel_policy.rs](../../packages/treetime/src/optimize/__tests__/test_indel_policy.rs). The optimized branch lengths of `Include` have one output check, the paired relation to `Exclude` on simulated gaps, which has not run yet. The optimized branch lengths of `Exclude` are compared with v0 only at loose tolerances.

## Evidence

- The timetree runner golden masters are `#[ignore]`d, so they do not run
- `fn test_gm_optimize()` [packages/treetime/src/optimize/__tests__/test_gm_optimize.rs#L23-L47](../../packages/treetime/src/optimize/__tests__/test_gm_optimize.rs#L23-L47) compares the total branch length of both policies with one v0 fixture at `max_relative = 0.05`. v0 has no indel term, so the fixture is a valid oracle only for the `Exclude` policy, and the `Include` policy passes only because the tolerance admits its difference
- `fn test_gm_optimize_per_branch()` [packages/treetime/src/optimize/__tests__/test_gm_optimize.rs#L50-L90](../../packages/treetime/src/optimize/__tests__/test_gm_optimize.rs#L50-L90) compares each branch length at `max_relative = 0.10`, but it is `#[ignore]`d ([M-optimize-gm-per-branch-divergence.md](M-optimize-gm-per-branch-divergence.md)) and runs only the `Include` policy, so no per-branch comparison against v0 runs for either policy
- Both tolerances predate the indel policy and are loose, so a regression of a few percent in `Exclude` passes
- `Include` against `Exclude`: [packages/treetime/src/optimize/__tests__/test_sim_optimize_indel_policy.rs](../../packages/treetime/src/optimize/__tests__/test_sim_optimize_indel_policy.rs) runs both policies on the true topology of simulated trees whose alignments carry gap events that never share or touch a site, for dense and sparse partitions. In the Poisson limit of the substitution likelihood, an edge of length $t$ under `Exclude` with $k$ gap events optimizes under `Include` to $(L_e t + k)/(L_e + \mu)$, where $L_e$ is the number of sites without a gap in the child and $\mu$ is TreeTime's indel rate in events per unit branch length. The test requires the mean log ratio of the `Include` length and this prediction to stay within 0.01, separately for branches with and without gap events, and $\mu$ to equal the event count over the total start length. For JC69 the error of the Poisson limit is of the order $10^{-3}$ at the branch lengths of the test: about $\frac{4}{3} k / L$ on gap branches and $\frac{2}{3} t \rho$ on the others, with $\rho = \mu / L$ the indel events per substitution and $L$ the alignment length
- The messy data of `validation/` checks the same relation (variant `fixed-topo` against `fixed-topo-noindel`, reported by `validation/analyze.py`). There, $\rho$ and $k$ come from the true gap events in `gaps.tsv`, so the check also tests the gap reconstruction. TreeTime's own $\mu$ is the `indel_rate` of the model output

> [!IMPORTANT]
> **Investigation required.** The paired-relation tests are in the slow tier and have not run yet: run `just test-slow-rs -E 'test(/test_sim_optimize_indel_policy/)'`. A failure is either a defect of the `Include` policy or a margin that the error of the Poisson limit does not support; trace which before changing the margin.

> [!IMPORTANT]
> **Investigation required.** For `Exclude`, the existing v0 fixture applies at a tolerance that the evidence supports; measure the actual difference before tightening.

# The Electron IPC request types are hand-written zod schemas

The requests and answers that the desktop renderer sends to the Electron main process (file and folder dialogs) are defined as hand-written zod schemas in `packages/app-contracts/src/files.ts`: `zPickFilesRequest`, `zPickedFiles`, `zPickFolderRequest`, `zPickedFolder`. The project rules define every value that crosses a process boundary, Electron IPC included, as a Rust type deriving its JSON schema, with the TypeScript types and zod validators generated by `just gen`. These four are the only IPC values outside that pipeline.

## Evidence

- `packages/app-contracts/src/files.ts` declares the schemas with `z.strictObject` and `z.array` by hand
- `packages/app-desktop/src/main.ts` validates incoming IPC requests with them, and `packages/app-desktop/src/desktop-shell.ts` validates the answers
- No Rust type or generated schema describes them; `dev/generated` has no group for IPC values

## Impact

- A change to a dialog request needs a matching hand edit on both sides of the IPC channel, which the generated-file check cannot catch
- Low: the values are small and used by one renderer and one main process

## Options

- Define the dialog requests as Rust types with `JsonSchema` and add them to a generated schema group that `just gen` turns into zod validators
- Keep them in TypeScript and record an exception for IPC values that never reach Rust

## Locations

- `packages/app-contracts/src/files.ts`
- `packages/app-desktop/src/main.ts`: `pickFiles`, `pickFolder`
- `packages/app-desktop/src/desktop-shell.ts`: `createLocalFiles`, `createWorkspaceShell`

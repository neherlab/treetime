# Resampling past a hard end moves the end out to the next grid point

`fn DistributionFunction::resample()` [packages/treetime-distribution/src/distribution_core/function.rs#L167-L177](../../packages/treetime-distribution/src/distribution_core/function.rs#L167-L177) evaluates the function at every point of the new grid through `fn GridFn::resample_with_extrap()` [packages/treetime-grid/src/grid_fn.rs#L379-L390](../../packages/treetime-grid/src/grid_fn.rs#L379-L390), with the boundary laws of the function. A new grid point beyond a hard end (a `Hard` side, or beyond `t_hard` of a `HardApproach` law) gets the cost `+inf`, and the resampled function keeps the old boundary laws. The resampled function does not know the old end: in a cell with one infinite and one finite sample, `fn GridFn::hard_cell()` [packages/treetime-grid/src/grid_fn.rs#L150-L171](../../packages/treetime-grid/src/grid_fn.rs#L150-L171) puts the hard bound at the infinite sample (`t_boundary`, line 164) and fits a hard-approach law from that sample to the finite samples. It reuses the stored law only in the first or last cell, and only when its `t_hard` coincides with the infinite sample. The cost between the infinite sample and the old hard end is therefore finite, and the support grows outward by up to one cell of the new grid.

Example: the function on `[1, 3]` with costs `3, 2, 1` and `Hard` sides, resampled with `resample_range_dx((0.0, 4.0), 0.5)`, stores `+inf` at 0 and 0.5, as `test_function_resample_beyond_hard_ends_has_infinite_cost` [packages/treetime-distribution/src/distribution_core/**tests**/test_function.rs#L77-L94](../../packages/treetime-distribution/src/distribution_core/__tests__/test_function.rs#L77-L94) asserts. The cell `[0.5, 1]` is a hard cell with its bound at 0.5, so the resampled function has a finite cost at 0.75, where the input has `+inf`. A `HardApproach` side with `t_hard = 0.25` gives the same result in the cell `[0, 0.5]`: the stored law does not coincide with the infinite sample at 0, so the refit law puts the bound at 0 and gives a finite cost at 0.1.

The same mechanism applies inside the grid: an input with a run of infinite samples (a gap in the support) that is resampled onto a grid whose points fall into the gap puts each edge of the gap at the next infinite sample of the new grid.

> [!IMPORTANT]
> **Investigation required.** Whether a production distribution reaches `fn resample_to_mass_window()` with an interior run of infinite samples, where the gap edges move as described above. Collect the count of such inputs per caller on the timetree smoke datasets with a temporary probe.

> [!IMPORTANT]
> **Decision required.** The fix of the resampling past a hard end. Options:
>
> - Keep the old end: the resampled function stores the old hard end as a boundary law of its first or last cell (a `HardApproach` law whose `t_hard` is the old end), and `fn GridFn::hard_cell()` takes the bound from that law also when it lies inside the cell
> - Clip the grid: the resampling ends the new grid at each hard end of its input, so no new sample lies beyond it; a caller that needs a fixed grid gets a shorter one
> - Reject the call: the resampling returns an error for a grid that extends past a hard end, because no production caller needs it

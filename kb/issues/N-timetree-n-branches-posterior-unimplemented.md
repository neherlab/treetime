# --n-branches-posterior returns error

The timetree command accepts the hidden flag `--n-branches-posterior` (`Option<usize>`, `hide = true`) [packages/app-commands/src/commands/timetree/args.rs#L293-L297](../../packages/app-commands/src/commands/timetree/args.rs#L293-L297), and the config schemas list it as `n_branches_posterior`. `fn validate_params()` of the timetree pipeline then rejects any value with `OperationError::InvalidParams` and the message "--n-branches-posterior is not yet implemented" [packages/treetime/src/timetree/pipeline.rs#L204-L209](../../packages/treetime/src/timetree/pipeline.rs#L204-L209).

In v0 the flag is a boolean (`action='store_true'`, [packages/legacy/treetime/treetime/argument_parser.py#L311-L318](../../packages/legacy/treetime/treetime/argument_parser.py#L311-L318)). It selects how `Coalescent.calc_branch_count()` computes the lineage count $k(t)$: from the point times of the nodes (default), or from their marginal posterior time distributions [packages/legacy/treetime/treetime/merger_models.py#L84-L114](../../packages/legacy/treetime/treetime/merger_models.py#L84-L114).

The v1 coalescent prior always computes expected lineage counts from node time distributions: `fn LineageExpectation::from_gaussian()` from the Gaussian node marginals in the init phase [packages/treetime/src/coalescent/mean_field.rs#L202](../../packages/treetime/src/coalescent/mean_field.rs#L202), and `fn LineageExpectation::from_posterior()` from the survival function of each node's posterior afterwards, with a point time only for a node without a posterior distribution [packages/treetime/src/coalescent/mean_field.rs#L182-L200](../../packages/treetime/src/coalescent/mean_field.rs#L182-L200). The v0 point-time default has no v1 counterpart.

> [!IMPORTANT]
> **Decision required.** What the flag becomes. Options: (a) remove the flag from the arguments, the config schemas and the pipeline params, because v1 always uses posterior lineage counts; (b) implement it as a boolean switch to point-time lineage counts, the v0 default. Evidence: the v1 flag takes an integer that v0 does not have, and the v1 prior has no point-time lineage counts (see [kb/decisions/timetree-frozen-lineage-counts-for-coalescent-prior.md](../decisions/timetree-frozen-lineage-counts-for-coalescent-prior.md)).

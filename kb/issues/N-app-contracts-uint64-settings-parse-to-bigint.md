# Generated zod schemas turn 64-bit integer settings into `bigint`

The generated zod schemas parse settings of Rust type `u64` (for example `seed`) with `z.coerce.bigint()`. A config parsed by `zTimetreeConfig` therefore holds `seed` as a `bigint`, and `JSON.stringify` throws on a `bigint`, so the parsed config cannot be sent to the server or the desktop addon as it is.

## Evidence

- `seed: z.coerce.bigint()...` in `packages/app-contracts/src/generated/zod.gen.ts`, generated by `@hey-api/openapi-ts` from the `"format": "uint64"` of the config schemas
- The same coercion applies to every `u64` and `i64` setting of the six command configs

## Impact

A form that validates a config with the generated zod schemas must convert `bigint` values back to numbers or strings before it sends the config.

## Potential solutions

- Configure the zod plugin of `@hey-api/openapi-ts` to parse 64-bit integers as numbers, accepting that JavaScript numbers are exact only up to 2^53
- Give the 64-bit settings a schema format the generator maps to `number`, when every accepted value fits in 2^53
- Keep `bigint` in the form and serialize it explicitly at the bridge

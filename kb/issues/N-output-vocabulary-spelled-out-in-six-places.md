# The output vocabulary is spelled out in six places

Every output is listed separately in `OutputSelection` and its `facts()` table ([packages/app-output/src/output_plan.rs](../../packages/app-output/src/output_plan.rs)), in `CommandKind::outputs()`, the per-command table of outputs and default rules ([packages/app-output/src/command_outputs.rs](../../packages/app-output/src/command_outputs.rs)), in the per-command selection enums and per-file flag lists that `command_outputs!` makes ([packages/app-commands/src/commands/shared/output_args.rs](../../packages/app-commands/src/commands/shared/output_args.rs)), in the per-file flag fields of each command's `args.rs`, and in `result_outputs()` that the UI reader uses ([packages/app-backend/src/results/outputs.rs](../../packages/app-backend/src/results/outputs.rs)). The `flag_name` column of `OutputSelection::facts()` restates the clap flag names. Adding one output means editing every list.

The test `packages/app-cli/src/__tests__/test_cli_output_lists.rs` checks the lists against each other: the `--output-selection` values and the per-file flags of each command against `CommandKind::outputs()` and the flag names of `facts()`, the default set of each command, and that `result_outputs()` names only outputs that the command writes. A list that drifts fails the test, but each list is still written by hand.

Remaining work: one table with one row per output (name, file extension, CLI flag, description, commands, default status) that every list derives from, so that the per-command enums and per-file flags are generated instead of checked.

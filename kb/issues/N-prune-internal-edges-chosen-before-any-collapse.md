# Prune chooses every internal edge to collapse before it collapses any

`fn prune_internal_nodes()` [packages/treetime/src/prune/prune.rs#L38-L79](../../packages/treetime/src/prune/prune.rs#L38-L79) first collects every internal edge that `--collapse-short`, `--collapse-empty` or a named node selects, from the branch lengths and mutation counts of the input, and then collapses the collected edges one by one. `fn collapse_edge()` [packages/treetime/src/optimize/topology/collapse.rs#L21-L82](../../packages/treetime/src/optimize/topology/collapse.rs#L21-L82) adds the length of the collapsed edge to each child edge and chains its mutations onto them. A child edge that was selected as short or empty is therefore collapsed even when the merge makes it longer than the threshold or gives it mutations.

`prune` reconstructs mutations whenever `--alignment` is given, so a run with `--collapse-short` and an alignment chains the mutations of each collapsed edge onto its child edges and writes them to the tree outputs, as `--collapse-empty` does.

v0 decides per node from the node's own branch length and does not add the removed length to the children [packages/legacy/treetime/treetime/treeanc.py#L1475-L1495](../../packages/legacy/treetime/treetime/treeanc.py#L1475-L1495). Because v0 never changes a child length, its decisions also use the unmodified input lengths, the same as the v1 selection. The difference from v0 is the length merge in `fn collapse_edge()`: v1 collapses the selected child edge and gives the merged length to its own children, while v0 drops the length of each removed edge.

> [!IMPORTANT]
> **Investigation required.** No wrong output has been shown. Find a tree where a selected child edge becomes longer than `--collapse-short` or gains mutations after its parent edge collapses, and compare the output branch lengths with v0. Decide from that comparison whether the length merge in `fn collapse_edge()` is correct for `prune`, or whether the selection must use the merged values.

## Proposed implementation plan

The plan stops at the open question above. Do the investigation first, then do one of the two fix options that the investigation selects.

1. **Reproduce.** Build a small tree by hand: an internal edge `p -> a` of length 0.004, an internal child edge `a -> b` of length 0.003, and leaves below `b`. Run `treetime prune --collapse-short 0.005` with and without `--alignment`. Expected v1 output: `a` and `b` both collapsed, and the leaf edges below `b` carry 0.007 plus their own length. Run v0 `prune_short_branches()` on the same tree for comparison. v0 has no threshold option: it removes a node when its branch length is below `0.1 * one_mutation` and the sequences of the node and its parent have a probability above 0.1 at length 0, so use an alignment of 20 sites (threshold 0.005) with identical sequences at `p`, `a` and `b`. v0 then drops the 0.004 and 0.003 and keeps the leaf lengths
2. **Decide.** Report the comparison to the user. The choice between "merge lengths, then select from merged values" and "drop the removed length as v0 does" changes output branch lengths, so it is a scientific choice that needs user approval and a `kb/decisions/` entry if v1 keeps a difference from v0
3. **Option A, select from merged values.** In `fn prune_internal_nodes()` (`packages/treetime/src/prune/prune.rs`), replace the up-front collection with a preorder walk that tests each internal edge with the current `branch_lengths` and the current mutation count (`fn get_edge_num_muts()`) just before it calls `fn collapse_edge()`. Named nodes (`node_keys`) keep their unconditional collapse
4. **Option B, v0 behavior.** Keep the up-front selection and make `prune` drop the removed length: add a parameter or a separate function next to `fn collapse_edge()` (`packages/treetime/src/optimize/topology/collapse.rs`) that skips the `bl1 + bl2` merge. Keep the merge for `fn collapse_short_internal_edges()` unless the decision covers optimize too
5. **Tests.** Add a unit test in `packages/treetime/src/prune/__tests__/` on the hand-built tree of step 1 that compares the whole output graph (topology and branch lengths). Oracle: the hand calculation of step 1 for the chosen option; for option B, also v0 `prune_short_branches()` on the same tree. Add a case with `--collapse-empty` where the parent edge carries one mutation and the child edge none, to cover the mutation chain
6. **Validate.** `just lint-rs`, `just test-rs`, and `just smoke` when the output of `prune` changes on a dataset

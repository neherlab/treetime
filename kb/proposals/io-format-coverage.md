# Format coverage for interoperability

TreeTime reads Newick trees, FASTA alignments, GFF3 annotations and delimited metadata. It writes Newick, Nexus, Auspice JSON, UShER <a id="gloss-use-1"></a>MAT <sup>[1](#gloss-1)</sup>, augur node data and FASTA ([kb/features/io.md](../features/io.md)). This proposal ranks the formats that TreeTime does not support yet. The ranking uses two criteria: use by established pathogen genomics tools, and fit with sparse mode and the graph model. Each actionable item has an issue in `kb/issues/`.

Two proposals design the shared machinery that these formats plug into:

- [kb/proposals/unified-input-format-support.md](unified-input-format-support.md): input paths that build partitions from formats with embedded sequence data
- [kb/proposals/output-format-selection.md](output-format-selection.md): output selection and per-file paths

## Gaps in widely used formats

- **UShER MAT as tree input**: `fn usher_mat_pb_read()` [packages/util-usher-mat/src/lib.rs#L56](../../packages/util-usher-mat/src/lib.rs#L56) parses MAT protobuf, but no command calls it. The UCSC Genome Browser builds MATs every day <a id="cite-1"></a>[McBroome et al. 2021](https://doi.org/10.1093/molbev/msab264) [[1](#ref-1)], for example for SARS-CoV-2 [[src](https://github.com/ucscGenomeBrowser/kent/blob/0c42aea56b751a2b4a58feb225a9659819a90994/src/hg/utils/otto/sarscov2phylo/updateCombinedTree.sh#L239)], mpox [[src](https://github.com/ucscGenomeBrowser/kent/blob/0c42aea56b751a2b4a58feb225a9659819a90994/src/hg/utils/otto/mpxv/buildTree.sh#L183)] and RSV [[src](https://github.com/ucscGenomeBrowser/kent/blob/0c42aea56b751a2b4a58feb225a9659819a90994/src/hg/utils/otto/rsv/buildTree.sh#L203)]. MAT input would let TreeTime add dates to these trees. A MAT stores mutations relative to a reference, which maps onto sparse partitions without a dense alignment. Issue: [kb/issues/N-io-usher-mat-input-not-wired.md](../issues/N-io-usher-mat-input-not-wired.md)
- **VCF input and output**: v0 reads and writes VCF, and UShER places samples from VCF <a id="cite-2"></a>[Turakhia et al. 2021](https://doi.org/10.1038/s41588-021-00862-7) [[2](#ref-2)]. The format is defined by <a id="cite-3"></a>[Danecek et al. 2011](https://doi.org/10.1093/bioinformatics/btr330) [[3](#ref-3)]. Issue: [kb/issues/M-io-vcf-input-output-unimplemented.md](../issues/M-io-vcf-input-output-unimplemented.md)
- **Nexus tree input**: BEAST, MrBayes and IQ-TREE write trees in Nexus, and v0 reads it. Issue: [kb/issues/M-io-nexus-and-phylip-input-unsupported.md](../issues/M-io-nexus-and-phylip-input-unsupported.md)
- **GenBank annotation input**: TreeTime reads GFF3 only. augur `translate` accepts GenBank or GFF [[src](https://github.com/nextstrain/augur/blob/0d287496eed3816f94d674f5a08201273f479487/augur/translate.py#L353)], and `usher_to_taxonium` takes a GenBank reference [[doc](https://github.com/theosanderson/taxonium/blob/ae4bceba28723d0b122330a7a8e1491601a97e2f/docs/taxoniumtools.md?plain=1#L28)]. Nextclade reads GFF3 only; its GenBank module writes NCBI feature tables [[src](https://github.com/nextstrain/nextclade/blob/629ea8fb0cfe3165db13ddc75dab16d3c2292dbd/packages/nextclade/src/io/genbank_tbl.rs#L14)]. Issue: [kb/issues/M-ancestral-genbank-annotation-unsupported.md](../issues/M-ancestral-genbank-annotation-unsupported.md)

## Newer formats

- **Taxonium JSONL output**: the file format of the Taxonium tree viewer <a id="cite-4"></a>[Sanderson 2022](https://doi.org/10.7554/eLife.82392) [[4](#ref-4)]. It is a <a id="gloss-use-2"></a>JSON Lines <sup>[2](#gloss-2)</sup> file: the first line holds tree metadata and a table of all mutations, and each later line holds one node [[doc](https://github.com/theosanderson/taxonium/blob/ae4bceba28723d0b122330a7a8e1491601a97e2f/docs/taxoniumtools.md?plain=1#L39)]. Each mutation has a gene, a previous residue, a position, a new residue and a type, `aa` or `nt` [[src](https://github.com/theosanderson/taxonium/blob/ae4bceba28723d0b122330a7a8e1491601a97e2f/taxoniumtools/src/taxoniumtools/utils.py#L194-L216)]. It can therefore carry amino-acid mutations, which MAT cannot [[src](https://github.com/yatisht/usher/blob/ac9c982d937c3bc43e2c16a0b73d30cf2b937118/parsimony.proto#L4-L11)]. The UCSC builds above and viral_usher [[src](https://github.com/AngieHinrichs/viral_usher/blob/5a2e7e65f7a7a6db7539e730fc59e2389ba3221e/viral_usher/viral_usher_build.py#L1235)] produce it. The format has no schema, so the `taxoniumtools` writer is its specification. The older Taxodium protobuf format is out of scope, because the current Taxonium code has no reader for it. Issue: [kb/issues/N-io-taxonium-jsonl-output-unsupported.md](../issues/N-io-taxonium-jsonl-output-unsupported.md)
- **MAPLE alignment input**: the alignment format of MAPLE <a id="cite-5"></a>[De Maio et al. 2023](https://doi.org/10.1038/s41588-023-01368-0) [[5](#ref-5)]. It lists the differences of each sample from a reference, so it is much smaller than FASTA for large, closely related datasets. CMAPLE reads it [[src](https://github.com/iqtree/cmaple/blob/3d45b1ab68e2d68a2825bf17a531e22200578cd6/alignment/alignment.h#L15-L18)] <a id="cite-6"></a>[Ly-Trong et al. 2024](https://doi.org/10.1093/molbev/msae134) [[6](#ref-6)], and IQ-TREE 3 can write it [[src](https://github.com/iqtree/iqtree3/blob/63c330d90dd02241dbbbaf1e9f9e9cc6dadbd1de/alignment/alignment.cpp#L6297)]. It maps directly onto sparse partitions. Issue: [kb/issues/N-io-maple-alignment-input-unsupported.md](../issues/N-io-maple-alignment-input-unsupported.md)
- **Nextclade NDJSON as alignment input**: Nextclade <a id="cite-7"></a>[Aksamentov et al. 2021](https://doi.org/10.21105/joss.03773) [[7](#ref-7)] writes one result per sample, with substitutions, deletion ranges and missing ranges relative to the reference [[src](https://github.com/nextstrain/nextclade/blob/629ea8fb0cfe3165db13ddc75dab16d3c2292dbd/packages/nextclade/src/types/outputs.rs#L73-L86)]. Sparse partitions could use these lists without a full alignment. No tool is known to read NDJSON as phylogenetic input, so this use is untested. Issue: [kb/issues/N-io-nextclade-ndjson-input-unsupported.md](../issues/N-io-nextclade-ndjson-input-unsupported.md)
- **tskit tree sequences**: sc2ts infers an <a id="gloss-use-3"></a>ARG <sup>[3](#gloss-3)</sup> for 2.48 million SARS-CoV-2 genomes and stores it in the tskit format <a id="cite-8"></a>[Zhan et al. 2023](https://doi.org/10.1101/2023.06.08.544212) [[8](#ref-8)]. A <a id="gloss-use-4"></a>tree sequence <sup>[4](#gloss-4)</sup> can represent a general ARG <a id="cite-9"></a>[Wong et al. 2024](https://doi.org/10.1093/genetics/iyae100) [[9](#ref-9)]. TreeTime's graph already supports networks ([kb/decisions/graph-based-phylogenetic-representation.md](../decisions/graph-based-phylogenetic-representation.md)). This item is the most speculative and the largest piece of work. Issue: [kb/issues/N-io-tskit-tree-sequence-input-unsupported.md](../issues/N-io-tskit-tree-sequence-input-unsupported.md)

## Low value

- **PhyloXML** <a id="cite-10"></a>[Han and Zmasek 2009](https://doi.org/10.1186/1471-2105-10-356) [[10](#ref-10)]: `packages/util-phyloxml` has a reader and a writer, but no package depends on it. The sources of augur, Nextclade, UShER, Taxonium and IQ-TREE 3 have no PhyloXML support. Issue: [kb/issues/N-io-phyloxml-crate-unused.md](../issues/N-io-phyloxml-crate-unused.md)
- **NeXML** <a id="cite-11"></a>[Vos et al. 2012](https://doi.org/10.1093/sysbio/sys025) [[11](#ref-11)], **and annotation files of tree viewers such as iTOL**: no known demand from TreeTime workflows. No issue

## Suggested order

1. UShER MAT input: the reader exists, and it opens the largest daily-updated trees to dating
2. VCF input and output: v0 parity, and UShER and augur use it
3. Taxonium JSONL output: the same viewer as the UCSC trees, with amino-acid mutations
4. MAPLE alignment input: a compact sparse input with a simple structure

## Glossary

1. <a id="gloss-1"></a> **MAT (mutation-annotated tree).** A tree whose branches carry the mutations that occur on them, relative to a reference sequence. UShER stores it as protobuf ([Turakhia et al. 2021](https://doi.org/10.1038/s41588-021-00862-7) [[2](#ref-2)]). [↩](#gloss-use-1)
2. <a id="gloss-2"></a> **JSON Lines.** A text format with one complete JSON value per line, also called NDJSON. A reader can process it one line at a time. [↩](#gloss-use-2)
3. <a id="gloss-3"></a> **ARG (ancestral recombination graph).** A genealogy in which a node can have more than one parent, so that recombinant lineages inherit different genome regions from different ancestors. [↩](#gloss-use-3)
4. <a id="gloss-4"></a> **Tree sequence.** The tskit data structure that stores a sequence of local trees along the genome as one table of nodes and edges, with each edge valid for a genome interval ([Wong et al. 2024](https://doi.org/10.1093/genetics/iyae100) [[9](#ref-9)]). [↩](#gloss-use-4)

# Per-edge branch length optimization: Brent and Newton-Raphson in sqrt(t) space

v1 offers two per-edge branch length optimization methods via `--optimizer`: Brent's method and Newton-Raphson, both in $\sqrt{t}$ space. The default `brent` uses the v0 method, Brent in $\sqrt{t}$ space, but differs from v0 in the search interval, the start, the objective penalty, the stopping tolerance, and the failure handling, so per-edge results can differ from v0 ([kb/issues/M-optimize-brent-setup-differs-from-v0.md](../issues/M-optimize-brent-setup-differs-from-v0.md)). v0 offers only Brent in $\sqrt{t}$ space.

## What v0 does

v0 `optimal_t_compressed()` ([packages/legacy/treetime/treetime/gtr.py#L816-L920](../../packages/legacy/treetime/treetime/gtr.py#L816-L920)) optimizes each branch length using Brent's method (Brent, 1973) with three design choices:

1. sqrt(t) reparameterization. The objective function takes `s = sqrt(t)` as input and computes likelihood at `t = s^2`. This reshapes the likelihood surface near zero, where `dL/dt` can be steep. The bracket is `[-sqrt(MAX_BRANCH_LENGTH), sqrt(hamming_distance), sqrt(MAX_BRANCH_LENGTH)]`.

2. Derivative-free. Brent's method combines golden section search (linear convergence, ratio ~0.618) with parabolic interpolation (superlinear, order ~1.325). It needs only function evaluations, no derivatives.

3. Hamming distance fallback. If `scipy.optimize.minimize_scalar` reports failure, v0 falls back to the raw Hamming distance between parent and child sequences as the branch length estimate.

v0 also adds a regularization penalty `exp(s^4/10000)`, that is $e^{t^2/10^4}$, when optimizing with marginal profiles (`profiles=True`) to prevent unbounded branch growth. In the code the argument of `_neg_prob` is named `t` but holds $s$.

## What v1 does

v1 `optimize_edge_lengths()` ([packages/treetime/src/optimize/dispatch.rs](../../packages/treetime/src/optimize/dispatch.rs)) offers two per-edge optimization methods selectable via `--optimizer`:

### Brent's method (derivative-free)

1. `brent` (default). Brent's method in $\sqrt{t}$ space via `argmin::BrentOpt`. The cost function evaluates $-\ell(s^2)$ and the interval endpoints transform as $\sqrt{\text{lower}}$, $\sqrt{\text{upper}}$, as in v0. It differs from v0 on the success path too: the interval is $[\max(t_\text{min}, 10^{-12}), \max(1.5\,t_0 + \text{one mutation}, 0.5)]$ instead of $t \le 4$, the solver starts at a golden-section point instead of the Hamming distance and can return a point slightly worse than the start, the objective has no penalty, and the tolerance is argmin's default $1.49\cdot10^{-8}\,\lvert s \rvert + 10^{-5}$ in $s$, set explicitly as `BRENT_REL_TOL` and `BRENT_ABS_TOL`, instead of v0's relative per-iteration schedule ([kb/issues/M-optimize-brent-setup-differs-from-v0.md](../issues/M-optimize-brent-setup-differs-from-v0.md)). Tolerance $\epsilon_s$ in $s$-space maps to $t$-space precision $\approx 2s^* \epsilon_s$, tighter near zero. Differs from v0 on solver failure: v1 surfaces an error to the caller via `Result<EdgeSolution, Report>`, while v0 silently substitutes the raw Hamming distance when SciPy reports non-convergence. At argmin's iteration limit, v1 keeps the best point and reports the edge in the run warning. When argmin converges within 3 tolerances of the upper end of the interval (the accuracy that argmin states for its result) and the cost at the upper end is lower than one tolerance below it, the likelihood still rises at the bound, and v1 reports the edge as stopped at the search bound. The status changes only the warning; the branch length is argmin's result.

### Newton-Raphson (analytical derivatives)

The substitution Hessian (posterior variance of eigenvalues) is computed in the centered Welford form $\sum_c w_c (\lambda_c - \bar\lambda)^2$, which avoids the catastrophic cancellation of the two-moment form $E[\lambda^2] - E[\lambda]^2$ when the posterior is tightly peaked.

2. `newton`. Safeguarded Newton-Raphson in $\sqrt{t}$ space with analytical derivatives from eigendecomposition-based coefficient caching. Reparameterizes as $s = \sqrt{t}$ and applies the chain rule: $d\ell/ds = 2s \cdot d\ell/dt$, $d^2\ell/ds^2 = 4s^2 \cdot d^2\ell/dt^2 + 2 \cdot d\ell/dt$. Reduces the Poisson indel Hessian singularity from $O(1/t^2)$ in $t$ space to $O(1/t)$, so the indel term dominates the substitution Hessian on short branches less than in $t$ space. `fn newton_sqrt_maximize()` ([packages/treetime/src/optimize/method_newton.rs](../../packages/treetime/src/optimize/method_newton.rs)) safeguards the iteration in four ways:

- **Bracket.** The search interval is $[\sqrt{\text{lower}}, \sqrt{\text{upper}}]$, with $\text{lower} = 0$, or $0.01 \cdot \text{one mutation}$ on edges whose indel term needs a positive length, and $\text{upper} = \max(1.5\,t_0 + \text{one mutation}, 0.5)$. This is the heuristic interval of Brent and the grid search; it is not justified as a general domain that contains the maximum ([kb/issues/M-optimize-brent-setup-differs-from-v0.md](../issues/M-optimize-brent-setup-differs-from-v0.md)). The search stays inside the interval. A start outside it with a finite log-likelihood, such as a positive start below the indel floor, is evaluated and kept as the incumbent: the search begins at the nearest end of the interval, and the method returns the start when no point of the search has a higher log-likelihood. A start with log-likelihood $-\infty$ is only clamped into the interval. Every evaluated point with $d\ell/ds > 0$ becomes the lower end of the bracket and every point with $d\ell/ds < 0$ the upper end, so the bracket always holds a local maximum or a maximizing interval end
- **Bounded steps.** A step is $-\ell'_s/\ell''_s$, limited so that $t$ grows by at most 1 and $s$ stays non-negative, then clamped to the search interval. At a non-concave point ($\ell''_s > 0$) the step uses $-\lvert\ell''_s\rvert$, so it still goes uphill. The iteration bisects instead when the step leaves the bracket, when the curvature is zero, at a stationary minimum (such as $s = 0$ with $d\ell/dt(0) > 0$), and when an uphill step at a non-concave point is within the tolerance, because such a step barely moves away from a minimum. The bisection halves the larger of the two parts into which the current point splits the bracket, so it never proposes the current point again; when the slope is not zero, the current point is an end of the bracket and the bisection takes the midpoint of the bracket
- **Likelihood check.** Every proposed point is evaluated, and the method returns the best evaluated point including the start, so the result is never worse than the start
- **Convergence report.** The method reports convergence only when the best evaluated point of the search is the current point and satisfies a maximum condition. Either the curvature is negative and the Newton distance $\lvert\ell'_s/\ell''_s\rvert$ is at most the tolerance $\varepsilon_s$, and then the method evaluates one more Newton step and returns the better of the two points; or the bracket is narrower than $\varepsilon_s$, which also covers an interval end where the slope points out of the interval; or slope and curvature are both zero and neither neighbor $s \pm \varepsilon_s$ inside the interval has a higher log-likelihood. The last condition accepts the exactly flat log-likelihood of an edge without information and rejects a flat stationary minimum such as $s = 0.5$ of $(s - 0.5)^4$, where the search continues by bisection. A stationary minimum, a step that does not move, and a local maximum below an earlier evaluated point do not count. After 50 steps the method returns the best point and reports the edge in the run warning. The limit of 50 steps is a budget, not a guarantee of convergence: bisection alone needs about $\lceil \log_2(W/\varepsilon_s) \rceil$ steps for a bracket of width $W$ in $s$ and tolerance $\varepsilon_s$, accepted Newton steps need not halve the bracket, and $W$ has no fixed bound because the upper end grows with $t_0$. IQ-TREE allows 100 Newton steps per branch
- **Accuracy.** The tolerance is $\varepsilon_s = \max(\min(5\cdot10^{-4}\,s,\ \delta_s),\ 10^{-8})$ with $\delta_s = 10^{-6} / (\sqrt{s^2 + 10^{-6}} + s)$. Every point within $\delta_s$ of $s$ has a branch length within $10^{-6}$ of $s^2$, because $(s + \delta_s)^2 - s^2 = 10^{-6}$ and $s^2 - (s - \delta_s)^2 < 10^{-6}$. The stopping rule therefore bounds the Newton distance estimate and the bracket width by $10^{-6}$ in $t$ on the whole search interval, the project limit for numerical error; the relative term $5\cdot10^{-4}\,s$ is the tighter one for $t < 10^{-3}$. The Newton distance estimates the distance to the maximum only where the surface is close to quadratic. `test_prop_optimize_method_newton_safeguard_matches_poisson_maximum` checks an error of at most $10^{-6}$ in $t$ on the Poisson surface for $s \le 3$; without the cap $\delta_s$, a start at $s = 2.9986$ with the maximum at $s = 3$ stopped with an error of $1.96\cdot10^{-6}$
- **Search bound.** When the search stops within $\varepsilon_s$ of the upper end of the interval and the slope at the upper end is positive, the likelihood still rises beyond the heuristic bound, and the method reports the status "stopped at the search bound" instead of convergence. The lower end is not a search bound in this sense: it is $t = 0$ or the indel floor, where a descending slope gives a valid boundary maximum

**Wrong-sign curvature: coraxlib's ascent step, not IQ-TREE's bisection.** At a non-concave point, IQ-TREE bisects the bracket ([optimization.cpp#L450-L458](https://github.com/iqtree/iqtree3/blob/63c330d90dd02241dbbbaf1e9f9e9cc6dadbd1de/utils/optimization.cpp#L450-L458)), and coraxlib steps uphill by $\ell'_s/\lvert\ell''_s\rvert$ ([newton.c#L185-L188](https://github.com/Exelixis-Lab/coraxlib/blob/5849dd2c72ac2ac2d9e182f75a5bbcfb476c4fa3/src/corax/optimize/newton.c#L185-L188)). v1 uses the coraxlib step. The first bracket reaches from the start to the end of the search interval in the uphill direction, so a bisection there moves halfway to that end, which can be far from the start and in another basin of a multimodal surface. The ascent step uses the slope and the size of the curvature at the current point and stays near it, and the bracket check still falls back to bisection whenever the step leaves the bracket. The ascent step is not proven to converge faster than bisection; the tests cover its result on the analytic Poisson surfaces and on the K80 surface below.

The bracket combines the derivative-sign bracket of IQ-TREE (`Optimization::minimizeNewton()`, [optimization.cpp#L422-L499](https://github.com/iqtree/iqtree3/blob/63c330d90dd02241dbbbaf1e9f9e9cc6dadbd1de/utils/optimization.cpp#L422-L499)) and coraxlib (`corax_opt_minimize_newton_multi()`, [newton.c#L93-L227](https://github.com/Exelixis-Lab/coraxlib/blob/5849dd2c72ac2ac2d9e182f75a5bbcfb476c4fa3/src/corax/optimize/newton.c#L93-L227)) with the likelihood check that coraxlib applies only in its `CORAX_OPT_BLO_NEWTON_SAFE` mode ([opt_branches.c#L34-L37](https://github.com/Exelixis-Lab/coraxlib/blob/5849dd2c72ac2ac2d9e182f75a5bbcfb476c4fa3/src/corax/optimize/opt_branches.c#L34-L37)). Neither safeguard finds a global maximum on a multimodal surface: on the K80 surface of [Dinh and Matsen 2015](https://arxiv.org/abs/1507.03647), with a local maximum at $t \approx 0.167$ and the global maximum at $t \approx 6.37$, starts at $t_0 = 0.05$ and $0.6$ reach the local maximum, and $t_0 = 5$ reaches the global one (`test_dispatch_zero_boundary_solve_newton_never_worse_than_start_and_converges_on_dinh_matsen_k80`).

Both methods share:

- The upper end $\max(1.5\,t_0 + \text{one mutation}, 0.5)$ of the search interval.
- Zero-branch short-circuit using the derivative-sign criterion at $t = 0$ for unimodal models (JC69, F81).
- Comparison of the solver result with $t = 0$ afterwards (`fn reconcile_zero_boundary()`), which runs a 100-point log-spaced grid search when zero beats the result, or when the result is zero but zero is not certified as the maximum or not admissible.

## Why v1 offers method selection

**One parameterization.** The $\sqrt{t}$ parameterization is the v0 parameterization and improves numerical conditioning on short branches and indel-bearing edges. Both methods use it, so a change of `--optimizer` changes only the solver.

**Newton-Raphson for analytical derivatives.** v1's eigenvalue-space coefficient caching (`k_c`) computes the likelihood as `sum_c k_c exp(lambda_c * t)`. The first and second derivatives follow by multiplying `k_c` by `lambda_c` and `lambda_c^2`, reusing the same exponentials. Newton achieves quadratic convergence near the optimum (3-5 iterations typical vs 10-30 function evaluations for Brent).

**Brent for robustness.** Brent's method is derivative-free and guaranteed to converge within the bracket. It serves as both a reference implementation and a fallback for cases where Newton behaves poorly.

**Default is the v0 method.** The `brent` default keeps v0's solver and parameterization without configuration; the setup differences from v0 are recorded in [kb/issues/M-optimize-brent-setup-differs-from-v0.md](../issues/M-optimize-brent-setup-differs-from-v0.md).

## Tradeoffs

**sqrt(t) reparameterization.** Used by `brent` (default; the interval, start, objective, tolerance, and failure handling differ from v0, see [kb/issues/M-optimize-brent-setup-differs-from-v0.md](../issues/M-optimize-brent-setup-differs-from-v0.md)) and `newton`.

**Still lost: regularization penalty.** v0 adds `exp(s^4/10000)` ($e^{t^2/10^4}$) when optimizing with profiles. v1 does not apply this penalty. The upper end of the search interval, shared by both methods and the grid search, limits the growth of a branch length per optimization round.

**Still lost: Hamming distance fallback.** v0 returns raw Hamming distance when Brent reports failure. v1 has no equivalent: solver errors propagate through `Result<EdgeSolution, Report>` to `optimize_edge_lengths`, which surfaces them to the caller; at the iteration limit both methods keep their best point. Each command run raises at most one `branch-lengths-not-converged` run warning. It names every edge that reached the iteration limit, or stopped at the upper end of the search interval with the likelihood still rising, in any optimization round of the run, and it counts these edges and the affected rounds. v1 prefers a loud error over v0's silent substitution because the silent fallback biased downstream branch lengths and made likelihood comparisons unreliable.

**Gained: method selection.** Users can choose between Brent's method and Newton-Raphson via `--optimizer`, matching the pattern in the `clock` command's `--branch-split-method`.

## Practical impact

For end-users, the per-edge optimization method is invisible when the edge log-likelihood has one maximum in the search interval: both methods then approach it within their tolerances. On a surface with several maxima they can stop at different ones, because Brent samples the interval from a golden-section point and Newton starts at $t_0$. On the indel-bearing edge of `test_optimize_method_cross_method_lh_agreement` (1, 2, and 4 indels) the two methods' edge log-likelihoods agree within $10^{-9}$, Newton's being the higher; Brent's absolute tolerance of $10^{-5}$ in $s$ explains the difference. Outputs of the two methods are not compared on the example datasets.

The outer loop applies no damping by default (`--damping`, default 0; v0 damps with 0.75). Optimizing edges in series as one sum removes the 2-cycle that an undamped loop with independent edge updates would produce ([optimize-damping-disabled-by-default.md](optimize-damping-disabled-by-default.md), [optimize-series-edges-joint-sum.md](optimize-series-edges-joint-sum.md)).
